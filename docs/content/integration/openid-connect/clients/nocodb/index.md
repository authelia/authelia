### Assumptions

This example makes the following assumptions:

- **Application Root URL:** `https://nocodb.{{< sitevar name="domain" nojs="example.com" >}}/`
  - This option determines the redirect URI in the format of
    `https://nocodb.{{< sitevar name="domain" nojs="example.com" >}}/sso/<provider-id>/redirect`
    where `<provider-id>` is a value generated by [NocoDB] when the provider is created.
    This means if you change this value, you need to update the redirect URI.
- **Authelia Root URL:** `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/`
- **Client ID:** `nocodb`
- **Client Secret:** `insecure_secret`

Some of the values presented in this guide can automatically be replaced with documentation variables.

## Configuration

### Authelia

The following YAML configuration is an example **Authelia** [client configuration] for use with [NocoDB] which
will operate with the application example:

```yaml {title="configuration.yml"}
identity_providers:
  oidc:
    ## The other portions of the mandatory OpenID Connect 1.0 configuration go here.
    ## See: https://www.authelia.com/c/oidc
    clients:
      - client_id: 'nocodb'
        client_name: 'NocoDB'
        client_secret: '$pbkdf2-sha512$310000$c8p78n7pUMln0jzvd4aK4Q$JNRBzwAo0ek5qKn50cFzzvE9RXV88h1wJn5KGiHrD0YKtZaR/nCb2CJPOsKaPK0hjf.9yHxzQGZziziccp6Yng'  # The digest of 'insecure_secret'.
        public: false
        application_type: 'web'
        authorization_policy: 'two_factor'
        require_pkce: false
        pkce_challenge_method: ''
        redirect_uris:
          - 'https://nocodb.{{< sitevar name="domain" nojs="example.com" >}}/sso/<provider-id>/redirect'
        scopes:
          - 'openid'
          - 'offline_access'
          - 'profile'
          - 'email'
        response_types:
          - 'code'
        grant_types:
          - 'authorization_code'
          - 'refresh_token'
        access_token_signed_response_alg: 'none'
        userinfo_signed_response_alg: 'none'
        token_endpoint_auth_method: 'client_secret_basic'
```

### Application

{{< callout context="note" title="Note" icon="outline/info-circle" >}}
[OpenID Connect 1.0] single sign-on is only available in the Business plan and above of [NocoDB], for both NocoDB
Cloud and licensed self-hosted deployments.
{{< /callout >}}

To configure [NocoDB] there is one method, using the [Web GUI](#web-gui).

#### Web GUI

To configure [NocoDB] to utilize Authelia as an [OpenID Connect 1.0] Provider, use the following instructions:

1. Login to [NocoDB] as an administrator.
2. Navigate to the single sign-on settings for your plan:
   - Business plan: navigate to the workspace `Settings` > `Single Sign-On (SSO)`.
   - Enterprise plan: open the user menu, select `Admin Panel`, then select `Single Sign-On (SSO)`.
3. Click `New Provider` and select `OpenID Connect (OIDC)`.
4. Configure the following options:
   - Display name: `Authelia`
   - Client ID: `nocodb`
   - Client Secret: `insecure_secret`
   - Authorization URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/authorization`
   - Token URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/token`
   - Userinfo URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/userinfo`
   - JWK Set URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/jwks.json`
   - Scope: `openid profile email offline_access`
   - Username Attribute: `email`
5. Copy the `Redirect URL` and replace the `redirect_uris` value in the Authelia configuration with it.
6. Click `Save`.
