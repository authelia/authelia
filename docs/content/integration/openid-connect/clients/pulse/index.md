### Assumptions

This example makes the following assumptions:

- **Application Root URL:** `https://pulse.{{< sitevar name="domain" nojs="example.com" >}}/`
  - This option determines the redirect URI in the format of
    `https://pulse.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/callback` when using the
    [Environment Variables](#environment-variables) method, or
    `https://pulse.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/<provider-id>/callback` when using the
    [Web GUI](#web-gui) method where `<provider-id>` is a value generated by [Pulse] when the provider is saved.
    This means if you change this value, you need to update the redirect URI.
- **Authelia Root URL:** `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/`
- **Client ID:** `pulse`
- **Client Secret:** `insecure_secret`

Some of the values presented in this guide can automatically be replaced with documentation variables.

## Configuration

### Authelia

The following YAML configuration is an example **Authelia** [client configuration] for use with [Pulse] which
will operate with the application example:

```yaml {title="configuration.yml"}
identity_providers:
  oidc:
    ## The other portions of the mandatory OpenID Connect 1.0 configuration go here.
    ## See: https://www.authelia.com/c/oidc
    clients:
      - client_id: 'pulse'
        client_name: 'Pulse'
        client_secret: '$pbkdf2-sha512$310000$c8p78n7pUMln0jzvd4aK4Q$JNRBzwAo0ek5qKn50cFzzvE9RXV88h1wJn5KGiHrD0YKtZaR/nCb2CJPOsKaPK0hjf.9yHxzQGZziziccp6Yng'  # The digest of 'insecure_secret'.
        public: false
        application_type: 'web'
        authorization_policy: 'two_factor'
        require_pkce: true
        pkce_challenge_method: 'S256'
        redirect_uris:
          - 'https://pulse.{{< sitevar name="domain" nojs="example.com" >}}/api/oidc/callback'
        scopes:
          - 'openid'
          - 'profile'
          - 'email'
          - 'groups'
        response_types:
          - 'code'
        grant_types:
          - 'authorization_code'
        access_token_signed_response_alg: 'none'
        userinfo_signed_response_alg: 'none'
        token_endpoint_auth_method: 'client_secret_basic'
```

### Application

To configure [Pulse] there are two methods, using [Environment Variables](#environment-variables), or using the
[Web GUI](#web-gui).

#### Environment Variables

To configure [Pulse] to utilize Authelia as an [OpenID Connect 1.0] Provider, use the following environment
variables:

##### Standard

```shell {title=".env"}
PULSE_PUBLIC_URL=https://pulse.{{< sitevar name="domain" nojs="example.com" >}}
OIDC_ENABLED=true
OIDC_ISSUER_URL=https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}
OIDC_CLIENT_ID=pulse
OIDC_CLIENT_SECRET=insecure_secret
OIDC_SCOPES=openid profile email groups
OIDC_USERNAME_CLAIM=preferred_username
OIDC_EMAIL_CLAIM=email
OIDC_GROUPS_CLAIM=groups
OIDC_GROUP_ROLE_MAPPINGS=pulse-admins=admin
```

##### Docker Compose

```yaml {title="compose.yml"}
services:
  pulse:
    environment:
      PULSE_PUBLIC_URL: 'https://pulse.{{< sitevar name="domain" nojs="example.com" >}}'
      OIDC_ENABLED: 'true'
      OIDC_ISSUER_URL: 'https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}'
      OIDC_CLIENT_ID: 'pulse'
      OIDC_CLIENT_SECRET: 'insecure_secret'
      OIDC_SCOPES: 'openid profile email groups'
      OIDC_USERNAME_CLAIM: 'preferred_username'
      OIDC_EMAIL_CLAIM: 'email'
      OIDC_GROUPS_CLAIM: 'groups'
      OIDC_GROUP_ROLE_MAPPINGS: 'pulse-admins=admin'
```

#### Web GUI

To configure [Pulse] to utilize Authelia as an [OpenID Connect 1.0] Provider, use the following instructions:

1. Login to [Pulse] as an administrator.
2. Navigate to `Settings` > `Security` > `Single Sign-On`.
3. Add an OIDC provider.
4. Configure the following options:
   - Issuer URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}`
   - Client ID: `pulse`
   - Client Secret: `insecure_secret`
   - Scopes: `openid profile email groups`
   - Groups Claim: `groups`
5. Select `Show access restrictions & role mapping` and configure the `Allowed Groups` and `Group Role Mappings` as
   desired, for example mapping the `pulse-admins` group to the `admin` role.
6. Click `Save`.
7. Copy the `Callback / Redirect URL` from the saved provider card and replace the `redirect_uris` value in the Authelia
   configuration with it.
