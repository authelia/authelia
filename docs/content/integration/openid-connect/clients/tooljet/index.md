### Assumptions

This example makes the following assumptions:

- **Application Root URL:** `https://tooljet.{{< sitevar name="domain" nojs="example.com" >}}/`
  - This option determines the redirect URI in the format of
    `https://tooljet.{{< sitevar name="domain" nojs="example.com" >}}/sso/openid/<configuration id>` where
    `<configuration id>` is generated by [ToolJet].
    This means if you change this value, you need to update the redirect URI.
- **Authelia Root URL:** `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/`
- **Client ID:** `tooljet`
- **Client Secret:** `insecure_secret`

Some of the values presented in this guide can automatically be replaced with documentation variables.

## Configuration

### Authelia

The following YAML configuration is an example **Authelia** [client configuration] for use with [ToolJet] which
will operate with the application example:

```yaml {title="configuration.yml"}
identity_providers:
  oidc:
    ## The other portions of the mandatory OpenID Connect 1.0 configuration go here.
    ## See: https://www.authelia.com/c/oidc
    clients:
      - client_id: 'tooljet'
        client_name: 'ToolJet'
        client_secret: '$pbkdf2-sha512$310000$c8p78n7pUMln0jzvd4aK4Q$JNRBzwAo0ek5qKn50cFzzvE9RXV88h1wJn5KGiHrD0YKtZaR/nCb2CJPOsKaPK0hjf.9yHxzQGZziziccp6Yng'  # The digest of 'insecure_secret'.
        public: false
        application_type: 'web'
        authorization_policy: 'two_factor'
        require_pkce: false
        pkce_challenge_method: ''
        redirect_uris:
          - 'https://tooljet.{{< sitevar name="domain" nojs="example.com" >}}/sso/openid/<configuration id>'
        scopes:
          - 'openid'
          - 'email'
          - 'profile'
        response_types:
          - 'code'
        grant_types:
          - 'authorization_code'
        access_token_signed_response_alg: 'none'
        userinfo_signed_response_alg: 'none'
        token_endpoint_auth_method: 'client_secret_basic'
```

### Application

{{< callout context="caution" title="Important Note" icon="outline/alert-triangle" >}}
[OpenID Connect 1.0] single sign-on is a paid feature of [ToolJet].
{{< /callout >}}

To configure [ToolJet] there is one method, using the [Web GUI](#web-gui).

#### Web GUI

{{< callout context="tip" title="Help Wanted" icon="outline/rocket" >}}
We would love screenshots of this configuration!
{{< /callout >}}

To configure [ToolJet] to utilize Authelia as an [OpenID Connect 1.0] Provider, use the following instructions:

1. Login to [ToolJet] as a Super Admin for instance level single sign-on, or as an Admin for workspace level single
   sign-on.
2. Click the settings icon in the bottom left.
3. Navigate to `Settings` then `Instance login` for instance level single sign-on, or `Workspace Settings` then
   `Workspace login` for workspace level single sign-on.
4. Enable `OpenID Connect`.
5. Enable the provider using the toggle in the top right of the modal.
6. Click `Save changes` without configuring any other options.
7. Open the `OpenID Connect` modal again.
8. Copy the `Redirect URL` and replace the configured `redirect_uris` value in the Authelia configuration.
9. Configure the following options:
   - Name: `Authelia`
   - Grant type: `Authorization Code`
   - Client ID: `tooljet`
   - Client Secret: `insecure_secret`
   - Well known URL: `https://{{< sitevar name="subdomain-authelia" nojs="auth" >}}.{{< sitevar name="domain" nojs="example.com" >}}/.well-known/openid-configuration`
10. Click `Save changes`.
